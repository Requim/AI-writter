# P2 事实数据契约

## 范围

P2 建立规范实体、追加式事实版本、正文断言和确定性对照函数。当前没有新增对外 HTTP 接口，也没有接入自动生成、修订或归档路径；P3 负责接入，P4 负责事实台账界面和纠错提案审批。历史章节不回填，不从正文自动提升事实权威。

## 模块

- service/value_objects/story_fact.py：不可变数据契约、证据、校验发现与报告。
- infrastructure/database/story_fact_repository.py：复用 PostgresNovelRepository.async_session 的事实仓储，不建立第二套连接池。
- application/story_facts.py：已确认显式字段编译、来源摘要与最小规则对照。
- alembic/versions/0007_story_facts.py：三张新增表；从 0006 升级不修改旧表内容。

## 实体与事实

实体使用稳定 UUID 与小说内唯一 entity_key 标识，不能仅凭同名合并人物。别名只是展示元数据，不用于猜测身份。编译器使用小说 UUID 与角色 ID 生成稳定人物 ID，仅采信角色显式 surname，跳过 legacy_import 和缺失姓氏，支持欧阳等复姓。

规范事实与正文断言分开：

| 数据 | 表 | 语义 |
| --- | --- | --- |
| 规范实体 | story_entities | 人物、家族、地点、物品身份 |
| 规范事实版本 | story_fact_versions | 已确认事实或撤回记录，按主体与属性追加版本 |
| 正文断言 | story_fact_assertions | 当前稿件中的待校验陈述，不会自动成为事实 |

当前属性为 surname、family、ancestral_hall_owner、location、life_status。姓氏和生命状态使用文本；家族、祠堂归属、地点使用实体外键。仓储检查主体和目标类型，数据库复合外键同时限制租户与小说归属。

## 来源与修订

每条记录保留 source_kind、source_ref、source_version、quote 和原始内容 SHA-256。规范来源仅允许已确认角色设定、整书规划或人工确认；正文草稿只能产生断言。来源是否真的经过用户确认由上游可信服务负责，不能直接把模型自报的 confirmed 字段传给编译器。

append_fact 要求 expected_version 和 idempotency_key。仓储对所属小说加行锁：两个请求以同一个期望版本修正时只允许一个成功；同一幂等键只能重放完全相同的请求。旧版本不原地覆盖，撤回也是一个新版本。P2 不提供事实直接编辑或删除接口。

最新版本替代该主体/属性的当前规范定义。valid_from_chapter 和 valid_to_chapter 限定适用范围，范围外返回 unknown，不自动猜测旧版本仍适用。复杂时间线、多值亲属关系、知识状态和事实审批由后续阶段扩展。

## 规则边界

validate_assertions 只校验传入的显式断言，不代表全文事实覆盖率。正文摘要必须与当前稿匹配，引用原文必须存在。无断言、无对应规范事实、事实撤回、范围不符或版本歧义均为 unknown；已确认的同主体/属性值不同才产生 hard_conflict。报告附带双边证据、事实 ID 与版本。

回归样本包含：辛家祠堂明确误写成陆家所有、辛姓人物访问陆氏祠堂不误报、收养后保留原姓、复姓、证据失效、规范事实撤回和版本修正。不会只因为出现陆氏祠堂就推断与辛姓人物冲突。

## 验收与发布

测试使用显式 TEST_DATABASE_URL，库名必须以 _test 结尾。包括仓储隔离、同租户跨小说拒绝、SQL 外键约束、并发修正、幂等重放、版本历史、断言隔离及持久化到规则对照的闭环。

迁移验收覆盖 0006 → 0007 → 0006 → 0007，保留已有小说。另将生产逻辑备份恢复到同主机临时隔离库，验证 Alembic 从实际 0006 数据升级到 0007，小说和章节数量不变。备份不下载到本地，临时恢复数据在验收后清理。

生产回滚优先恢复旧应用镜像并保留新增表；不得自动 downgrade 删除事实历史。恢复整个生产库属于另一次操作，须确认备份时间和其后的业务写入，不能为回退应用盲目覆盖生产数据。

P1 旧镜像不包含0007迁移脚本，回滚必须使用进展文档 CP-005 的专用覆盖文件，直接启动 uvicorn，跳过旧 Alembic 入口；否则旧迁移器无法识别当前数据库版本。配置解析和旧镜像可执行程序已验证，未实际进行生产回滚。

初始迁移 0001/0002 仍依赖运行时 ORM 元数据，存在空库全链路初始化风险。本轮验证范围是现有 0006 数据的升级；后续发布工程阶段应冻结历史迁移元数据，并增加空库到 head 的独立验收，不将当前增量升级验证等同于全新安装验证。
