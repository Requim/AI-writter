# 采集失败修复与服务器验收

## 目标与边界

- AC-1：定位截图对应的真实批次错误，不将 worker 健康等同于来源可用。
- AC-2：恢复有界重试和备用候选补位，不绕过 403/429，不提高 200 次请求预算。
- AC-3：页面准确区分失败、部分完成、完成，具体错误保持可见。
- AC-4：检查共用采集路径和其他分类，核对真实页面、入库数量及知识版本。
- 不修改写作后端，不清理原有样本，不自动审核知识版本，不提交或推送 Git。

## 已确认的根因

原批次 `research-1790089889126`，创建于 2026-09-22，女频，目标 10，结果 0。
数据库错误为 `女频: BiqugeResearchError: 来源详情暂不可用：HTTP 520`。
线上旧适配器对 520 立即抛错，并把目录请求错误也写成“详情”错误。
该错误发生在候选发现阶段，并非 worker 没有运行。

服务器初次只读检查中，42/44/46/47/48/49/51 七个分类目录均返回 520。
女频裸域名与 www 域名也均返回 520。该现象不是女频单独配置错误。
后续真实复验中目录恢复响应，但多本详情页仍持续返回 520。

## 已发布修复

- 520 与其他 5xx 使用有界重试，错误保留目录/详情/章节阶段。
- 一个目录失败后继续调用方已配置的其他目录；相同 URL 不按分组重复请求。
- 403/429 保持立即拒绝，不通过备用目录绕过。
- 候选不足备用池数量时，仍采集实际存在的候选，不制造重复样本。
- 优先分层候选用尽后继续尝试同一目录已发现的剩余候选；请求预算不变。
- 修正零配额仍取走一个候选的抽样边界问题。
- 失败与部分完成使用正确终态；页面兼容历史 `phase=completed` 的失败记录。
- 失败与部分完成不自动折叠，错误原因不再只藏在折叠区。

研究服务和后端兼容适配器代码同步修复。生产实际更新独立研究 API、worker 和前端，
没有重启 `novel-writer-backend:materials-20260922-r2`。
