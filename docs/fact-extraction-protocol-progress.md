# 事实提取协议与旧失败恢复修复

日期：2026-09-17

## 目标与现场

- 用户在上一版部署后重试仍得到事实审校:outline耗尽错误。
- 同一作品的最新 checkpoint 已有 8 个实体和 8 条事实，证明空基线补建已生效。
- 当前 unknown 原因为事实提取未获得有效证据，findings 为空；不再是事实基线缺失。
- 只读检查当前后端两小时内日志：3 次结构化输出失败，每次均包含 `$defs`、`additionalProperties`、`properties`、`required`、`type` 缺失。
- 本轮没有启动真实模型调用、修改生产数据或部署。

## 根因与上一轮遗漏

- `evaluate_facts` 给适配器传入完整 Pydantic JSON Schema。
- 适配器接受的是“业务字段 -> 简单类型”的结构；将 JSON Schema 关键字视为必需业务字段，即使模型返回正确业务 JSON 也会拒绝。
- 原提示词还未明确告诉模型 coverage/claims/unresolved 的完整输出结构，适配器本身不把 schema 注入请求。
- 上次 smoke 与主要事实测试模拟 structured_generate 的最终结果，绕开了真实适配器校验，不能证明集成契约正确。
- 旧失败已耗尽预算；仅改模型调用而不处理这个检查点版本，仍会在重新提取前报错。

## 修改与约束

- 适配器只收到 coverage/claims/unresolved 的轻量结构，枚举、实体 ID、引用、关系值和额外字段继续由 Pydantic 与原归档校验检查。
- 完整输出契约在运行时附加到审校提示词，兼容已绑定旧模板快照的作品，不篡改已有创作提示词快照。
- 回执新增事实提取协议版本；旧回执默认 v1，新提取显式记录 v2。
- 仅旧版本 unknown/unknown 且无 findings 的报告允许协议升级重新审校；新报告落盘后，同证据不能重复重置耗尽次数。
- 旧版本回执摘要保持兼容，不使已有人工确认失效。
- 异常日志只记录异常类型和稿件种类，不记录模型响应、正文或凭据。
- 不把 unknown 直接当作 pass，不改变事实、证据与归档规则，不增大全局重试预算。

- 真实 OpenAIAdapter + 模拟网络返回覆盖：有效业务 JSON、旧快照契约注入、非法枚举/实体/引用、空响应、旧回执摘要兼容。
