# 后台自动推进

日期：2026-09-17

## 目标与边界

- AC-1：关闭网页只断开事件订阅，服务端任务继续执行。
- AC-2：已暂停书籍可从当前 checkpoint 切换为服务端自动推进，无需浏览器代点审核。
- AC-3：自动模式处理规划、简介、质量及事实审核；失败有限修复，不伪造人工确认，不跳过硬约束。
- AC-4：人工模式、取消、幂等及单节点超时保持有效；自动任务不受整轮十分钟截止限制。
- 本轮不提交、推送、部署，不调用付费模型。进程重启后的自动调度不属于已验证能力。

- 工作区有大量既有未提交改动，全部保留。
- 原服务端已有独立 asyncio 任务与断流保护；问题包含强制审核及整轮超时。

- 截图显示 `workflow_timeout`；未读取该运行的生产日志，不能据此认定当时服务端部署版本。

- 复用现有独立后台任务、执行锁、checkpoint、事件日志及租约续期，不新增重复任务系统。
- 所有流式执行（包含逐步确认模式）改用独立后台时限 `WORKFLOW_BACKGROUND_TIMEOUT_SECONDS`，默认 86400 秒；执行协程和命令租约使用同一预算，租约额外保留 120 秒结算缓冲。
- 旧同步 invoke 和章节重写入口的租约预算保持原值。不是取消所有时限，也不保证后端重启自动拉起。
- 单节点 240 秒及模型请求超时保护保留；区分依赖超时、节点超时与后台总时限，避免错误归类。
- 新增验证：后台入口策略接线、租约预算、后台时限终止与结算、真实节点截止、依赖超时分类；更新旧测试以确认逐步模式后台任务超过请求时限仍可完成。
