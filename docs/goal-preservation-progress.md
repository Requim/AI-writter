# 校验与修订的目标守恒

## 范围与基线

- 2026-09-10：保留现有工作流、事实门禁、提案、checkpoint 和章节事务，不新增 Agent 或模型调用。
- 新接受的整书计划章节绑定服务端目标契约，旧检查点无契约时保留兼容行为，不声称已通过新验收。
- 原始用户硬边界、已接受计划的必达事件、状态变化与终章结局作为目标来源；修订意见不是修改目标的授权。
- 字数目标与硬限制分开：章节分配是参考目标，整书规模与容差是硬约束，不由模型自报字数或“质量较好”放宽。

## 预先固定的验收例

1. 一章书目标 3000 字、容差 10%，4656 字即使评分满分也不能自动归档。
2. 必达项 A、B 中只提供 A 的正文证据，或 B 的引文不存在，不能判定目标完成。
3. 终章仍有延期事项不能当作已完成；安静章节不因此被要求追加冲突。
4. 正文修订、用户替换或目标来源变化后，旧正文验收结果不可复用。
5. 局部修订失败不得无声扩大为全文重写；已解决问题不得再作为修改依据。
6. 人工接受质量缺点不等价于变更目标或跳过目标验收。

## 实现记录

- `application/goal_contract.py` 从已接受的计划、用户简介、创作简报、作者硬边界编译目标，保存来源和指纹；模型细纲不能注入自己的目标契约。超过上下文预算时暂停，不截断约束。
- 接受细纲后契约随章节细纲进入 checkpoint 与章节产物；正文、场景续写、审读、定向修改及全文修订使用同一目标。原始目标若在此前阶段已经丢失，不能由这个模块凭空恢复。
- 审读增加逐项目标结果、真实正文引文及判定理由，缺项、重复项、伪造引用、未知结果均不通过。服务端独立计算实际字符数，终章检查整书规模及容差；已有正文计数缺失时保持未知，不当成 0。
- 人工接受修订仍回到审读，不复用旧正文结论；质量接受不能绕过目标门禁。归档同时核对目标指纹、正文指纹和逐项通过结果，事实门禁仍独立执行。
- 局部修改要求证据锚点，单项最多 1500 字符、累计最多正文 30%；失败不自动全文重构。完整重写需要明确指令或既有结构性审读路由，已解决问题不再作为修改依据。新契约章节不机械扩写到旧的全局字数下限。
- 修订记录保存目标指纹、前后正文指纹和修改指令；审读页面显示目标未满足项并禁用绕过验收的接受操作。“部分延后”更名为“存在计划偏差”，保留真实延期事项明细。

## 边界

- 语义判断仍由模型辅助，引用真实存在并不证明模型对因果的解释正确，真人效果验收仍独立。
- 本轮不自动改生产作品或原始目标。生产灰度、新模型实测与跨进程恢复需独立验证。
- 实现阶段未运行新改动的真实数据库、跨进程恢复、浏览器和真实模型效果验收；后续经用户明确要求部署，发布证据见下节，仍不等于真实模型效果验收。
- 逐字引文存在只证明证据可定位，不能机械证明自然语言因果解释正确；语义错误需要独立案例及真人评估继续检验，不把模型逐项报告当成绝对证明。
