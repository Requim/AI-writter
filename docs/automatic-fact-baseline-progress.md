# 自动创作事实基线修复

日期：2026-09-17

## 目标与边界

- 自动采用角色方案后应建立可追溯的显式角色事实，不依赖人工逐项确认。
- 已卡住的自动作品应能从同租户持久化的角色设定恢复事实基线，再审校原稿。
- 不猜测姓氏、不以正文草稿或客户端自报建立权威、不覆盖已有事实版本。
- 不提高修复次数上限，不把 unknown 当作 pass，不伪造人工审核回执。
- 本轮是本地修复和生产只读诊断，不包含提交、部署或生产数据修复。

## 线上证据

- 作品《没办过的那场聚会》，ID `e4371f19-11c4-4db1-aa20-618b5350a11b`。
- 检查点：chapter=0、auto_mode=true、schema=5、FACT_REVIEW_MODE=standard。
- 已保存角色 8 名，全部有显式 character_id 和 surname，无 legacy_import。
- 事实快照 entities=0、fact_heads=0；character_fact_source 为空。
- outline 报告为 unknown，原因是缺少已确认事实基线，findings 为空。
- 同一章节的事实审校:outline 已耗尽 2 次。
- 原因：角色审核自动接受分支跳过事实入账，而后续审校缺少基线必定返回 unknown；重复模型调用无法补足这个前置条件。

## 修复

- 角色审核自动接受时沿用原子、幂等事实入账，明确来源 auto: 与 automatic_policy。
- confirmed 表示已被服务端采用的故事设定，不等同于人工操作；不生成 reviewed_by 或 fact_acknowledgements。
- 自动生成和复核读取事实快照时，空台账只从小说仓储里同租户已保存角色补建显式姓氏事实。
- 补建来源 auto-saved: 绑定规范化角色内容哈希，重试复用；任何既有事实版本头均阻止自动补建，包括撤回及未生效版本。
- 旧失败现场先读取当前可信快照；只有 digest 改变才清除本章节当前稿件类型的事实修复预算并重新取证。其他阶段预算保留。
- 审校器和归档门禁保持不变，基线恢复后仍可能因真实矛盾、模型不可用或证据不足而失败。
