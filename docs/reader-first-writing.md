# 网文书名与开场改造

## 解决的问题

读者不知道人物在做什么，通常不是“词语不够像人”，而是正文没有及时交代
身份、关系、目标和行动后果。先修故事的信息组织，再修段落和句式。
书名同样先体现本书真实的故事承诺，不能靠抽象意象或不存在的热门设定骗点击。

## 实际生成链路

1. 新建作品时，由服务端在既有总纲 JSON 写入 `reader_quality_version=1`。
   客户端不能指定版本或传入验收回执；历史缺省值为 0，不迁移旧作品。
2. 根据确认简报生成八个书名候选，覆盖设定、冲突、关系和短名。
   服务端按卖点 30%、承诺清晰度 30%、题材 20%、记忆点 10%、自然度 10%
   重算百分制分数。自定义书名优先，旧候选按原协议使用。
3. 简报与前三章细纲分别列出现在必须理解的信息、可以暂缓揭晓的答案。
   必要事实必须进入第一场景的 `allowed_information`；冲突不能通过擅自
   授权事实解决。辅助写作与修订联合检查章节及总纲，遮蔽其他字段中重复的
   延迟答案。后续章节明确授权揭晓时，可以解除简报的开场延迟；当前章节
   自身的延迟要求仍有约束力。原始总纲和事实校验材料完整保留。
4. 将章节目标、动机、行动要求、阻碍、必要变化和收尾编译成自然语言委托，
   同时保留执行契约。允许直接说明关系与情绪、自然对白和必要术语；
   专业内容用人物用途与损失解释。
5. 首章前 500 字建立已出场人物身份、眼前关系和目标，前 800 字有阻碍
   与具体吸引点。二三章审读本章行动，并可承接已归档前文的身份关系。
6. 独立模拟试读只收到题材、正文与最多两章已归档正文，逐项回答人物、
   关系、目标、阻碍、吸引点。所有证据必须逐字存在，首章还复验位置。
   它看不到书名、简介、细纲、故事圣经和未来秘密。
7. 理解失败进入现有修订流程，文学高分不能抵消。结构失败重修开场，
   缺失信息回到对应场景补足，重复动作与同构段落局部删改。
   修后重审，不能靠章末追加说明通过首章验收。
8. 正文、提示词版本、章号、题材与已归档前文共同绑定回执；修稿或前文
   变化后失效。归档前再查回执。未变化的断点复用有效回执，避免重复付费。
   格式最多纠正一次，次数和预算仍受既有规则约束。

服务端独立读者模板不采用客户端或旧写作快照中的覆盖内容。试稿的复合审读
还绑定外层试读模板，使用单独的 `pilot` 回执范围，不能用于正式章节归档。
模型报告中的不清楚结论及阻断问题在格式纠正中不能被改为通过或删除。
人物绑定委托在新流程中只提供人物资料及人物 ID，避免存档记录 ID 混入角色身份。

## 验证边界

行为测试中的模型替身只用于验证接口、哈希绑定和路由，不证明真实成稿质量。
真实模型测试另存试稿、正式稿、修订、逐字证据和请求消耗，并保留失败样本。
所有盲读都是模型模拟，不等同真人读者评价或市场验证。

《你那份我没动》只作为失败样本读取，不改书名、正文、设定或历史归档。
九章真实成稿与上线冒烟的实际结果写入单独验收报告；未完成的项不会标成通过。
