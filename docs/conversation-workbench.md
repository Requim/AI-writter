# 对话创作工作台

本轮交付将小说创作的主入口改为作品内的对话工作台。作者可以讨论、完善设定、
规划大纲、写作、续写、改写和审读，选择回复全文或选段存入作品资产库。
原工作台和整书自动生成入口继续保留。

## 已实现

- 简单创建作品；会话新建、重命名、历史恢复。
- 后台生成与 SSE 状态流；断开页面不停止任务；主动停止和手动重试。
- 中断、模型失败和服务重启保留已经持久化的正文。重试使用同一额度身份，
  并保留最近五次未完成内容；并发重试只能排队一次。
- 单次回复最多 100000 字符，与资产正文容量一致；超限停止并保留已有正文，
  可以先存为资产再分段继续创作。
- 灵感、世界设定、人物、剧情大纲、章节草稿、参考资料六类资产。
  资产编辑使用版本校验，旧版本不可变，跨作品复制保留来源并独立编辑。
- 固定设定、故事起点和显式引用进入每轮上下文；改写或审读正式章节时携带
  目标章全文及版本。最近对话和现有分层记忆按预算加入。
- 基础 RAG 使用关键词和可用时的 `pg_trgm` 相似度，按段落检索当前有效设定
  和已采用章节。未采用草稿只通过作者显式引用进入上下文。
  每条回复可查看来源、版本、文本位置和原文；检索故障时显示降级状态。
- 保存草稿不修改正式章节。明确采用后才原子更新章节、字数进度、摘要、
  故事状态、检索索引和检查点恢复请求。审读绑定资产版本及作品上下文版本。
  可以选择审读通过、带问题采用或未经审读采用，结果会记录在正式章节上。
- 与原编辑器共用作品锁、章节乐观锁和检查点恢复机制。
  原编辑、改写和回退会同步更新或删除检索来源。
  打开作品只检查缺失索引，旧作品首次补建；完整重建通过显式操作触发。
- 所有接口按租户、作品校验会话、资产、任务和检索来源。

## 运行和开关

后端在 `writter_back` 运行。使用项目现有 Python 环境和模型配置，
先执行 `python -m alembic upgrade head`，再启动 FastAPI。
本轮新增迁移为 `0011_conversation_workbench`；迁移账号需要创建 `pg_trgm`
扩展的权限。没有该扩展的数据库仍可运行基础关键词检索。

`CONVERSATION_WORKBENCH_ENABLED=true` 开启后端创作功能。
前端默认将 `/novels/:novelId` 指向对话工作台；
`VITE_CONVERSATION_WORKBENCH=false` 可恢复原入口，需要重新启动或构建前端。
原工作台始终位于 `/novels/:novelId/studio`，
高级创建位于 `/novels/new/advanced`。

当前后台任务和作品互斥复用现有进程内调度，按 `WORKERS=1` 运行。
服务启动会将中断任务标记为失败，正文保留，作者可手动重试。
多进程部署需要先加入持久化任务领取、租约和停止信号，不应直接增加 worker。

本地验收实例使用 `.release/workbench-qa/postgres-data` 的独立 PostgreSQL，
前端为 `http://127.0.0.1:5173`，后端为 `http://127.0.0.1:8000`。
模型真实调用需要配置项目已有的对应 API 密钥。最初的本地实现阶段未连接生产。
2026-10-14 经用户明确要求，已发布至 `https://myunlimatedlife.top`，
并通过真实模型、资产入库、RAG 与公网页面验收。
完整发布和回滚记录见 `docs/workbench-production-20261014.md`。

## 验证边界

2026-10-13 最终验证结果：

- 后端：1357 项通过，包括 22 项工作台专项测试。全量命令为
  `python -m pytest -q --ignore=tests/test_process_restart.py --tb=short`，
  `TEST_DATABASE_URL` 指向本地独立 PostgreSQL 测试库。
- 前端：`npx vitest run --maxWorkers=4 --reporter=dot`，32 个测试文件、
  205 项通过；`npm run build` 通过。
- 新增工作台及相关接入文件的 Ruff、ESLint 检查通过；项目现有范围的
  mypy 检查通过；静态复杂度门禁和 `git diff --check` 通过。
- 真实 PostgreSQL 的完整迁移、回退至 `0010`、重新迁移至 `0011` 均通过。
- 浏览器：1440、820、390 像素宽度均无横向溢出，输入框保持可见；
  检查报告的页面错误列表为空。

后端测试使用原生 PostgreSQL，验证真实 HTTP、SSE、额度记录、资产版本、
检索、事务采纳、冲突、并发重试和租户隔离。只有外部模型使用受控响应。

`scripts/workbench_browser.cjs` 验证真实本地 API 的简单创建、会话恢复、
保存全文、保存选段、草稿不自动采用、关键词检索和原工作台入口；
成功回复正文使用明确的浏览器样本。截图及报告保存在
`.release/workbench-qa/browser`，检查桌面、平板和手机布局。

没有配置本地模型密钥；2026-10-14 生产环境的一次真实短回复已完成，
长篇生成质量、不同负载下的延迟及货币费用尚未验收。
Windows 无法收集原有 `tests/test_process_restart.py` 中的 `SIGKILL` 用例，
2026-10-14 已在 Linux 隔离环境执行，完整后端 1359 项通过。
不要把此前 Windows 通过数解释为覆盖了这些用例。
